03 · How I ship

Click through a release.

Every stage below is something I've built and run. Pick one to see what happens there.

A change enters the system

Feature branch, pull request, peer approval, and a JIRA ticket tying the change to an approved release. Nothing reaches a build without a reviewer and a record.

GitGitHubPR approvalsJIRAFeature branching

Built once, in one place

Jenkins shared libraries give Java, Node.js and Python teams the same pipeline instead of one each. The artifact built here is the exact artifact that reaches production — promoted, never rebuilt.

JenkinsShared librariesDockerMavenNPMpipECR

Security runs as a build stage

Four gates before anything ships: static analysis, dependency and code scanning, and container image CVEs. A failing scan fails the build — it doesn't become a note in a release review.

SonarQubeVeracodeRetinaECR image scanningShift-left

Infrastructure and release, both from code

Modular Terraform builds the VPC, security groups, IAM roles, node groups and ECR integration; Helm handles the release onto EKS. Rolling updates and cluster upgrades happen without taking the service down.

TerraformKubernetesEKSHelmAnsibleALB

You find out before the user does

Prometheus and Grafana watch CPU, memory and disk with automated alerts; ELK gives log-level tracing across VMs and EKS. HPA and multi-AZ keep things up when load moves.

PrometheusGrafanaNode ExporterELK stackHPAMulti-AZ
